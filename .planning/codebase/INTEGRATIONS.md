# External Integrations

**Analysis Date:** 2026-08-11

## APIs & External Services

**LLM / AI Providers (all called via `httpx` in `backend/services/rag/providers/` — no official SDKs):**
- **Ollama** (local, default provider) — RAG answer generation
  - Endpoint: `{OLLAMA_HOST}/api/generate`, default `http://localhost:11434` (`OLLAMA_HOST` in `backend/core/config.py`)
  - Model: `llama3` (overridable via `model_name` request field)
  - No auth required; payload `{"model", "prompt", "stream": false}` (`backend/services/rag/providers/ollama.py`)
- **OpenAI (ChatGPT)** — optional cloud provider
  - Endpoint: `https://api.openai.com/v1/chat/completions`
  - Auth: `OPENAI_API_KEY` env var, `Authorization: Bearer` header
  - Model: `gpt-3.5-turbo` default (`backend/services/rag/providers/openai.py`)
- **Google Gemini** — optional cloud provider
  - Endpoint: `https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent`
  - Auth: `GEMINI_API_KEY` env var, sent as **`x-goog-api-key` header** (not a URL query param — `backend/services/rag/providers/gemini.py`)
  - Model: `gemini-1.5-flash` default
- **xAI Grok** — optional cloud provider (OpenAI-compatible)
  - Endpoint: `https://api.x.ai/v1/chat/completions`
  - Auth: `GROK_API_KEY` env var, `Authorization: Bearer` header
  - Model: `grok-beta` default (`backend/services/rag/providers/grok.py`)
- Provider selection is per-request via `provider` field (`ollama` | `openai` | `gemini` | `grok`) in `backend/schemas.py` (`RAGQueryRequest`) and the dropdown in `frontend/src/components/AIAssistant.tsx`
- All provider calls share `post_json()` in `backend/services/rag/providers/_http.py`: bounded timeout (`LLM_TIMEOUT_SECONDS`, default 10s), retry backoff (`LLM_MAX_RETRIES`, default 1), raises `LLMError` on failure
- Unknown/invalid provider names are caught in `backend/services/rag/pipeline.py` (`_resolve_provider`) and safely fall back to the configured default provider
- Provider failures produce a friendly "language model is currently unavailable" answer with `confidence = 0.0` and `grounded = False` — never fabricated data

**Fonts CDN:**
- Google Fonts (Fredoka, Quicksand) — loaded at runtime in `frontend/index.html` from `fonts.googleapis.com` / `fonts.gstatic.com`

## Data Storage

**Databases:**
- SQLite (default dev) — primary relational store
  - Connection: `DATABASE_URL`, default `sqlite:///./cozy_productivity.db` (`backend/core/config.py`, `backend/database.py`)
  - Client: SQLAlchemy 2.x ORM; `users` + `tasks` tables (`backend/models.py`)
  - File: `backend/cozy_productivity.db`
- PostgreSQL 16 — production relational store
  - `postgres:16-alpine` service in `docker-compose.yml` with named volume `postgres_data`, healthcheck, credentials `cozy`/`cozy_pass`
  - Backend connects via `DATABASE_URL=postgresql://cozy:cozy_pass@db:5432/cozy_db` (`docker-compose.yml`); `psycopg2-binary` driver
  - `backend/database.py` auto-adjusts connect args (only SQLite needs `check_same_thread: False`)

**Vector Store:**
- ChromaDB ~0.5.0 — RAG memory embeddings
  - Client: `chromadb.PersistentClient(path=CHROMA_PATH)` where `CHROMA_PATH` default `./chroma_db` (`backend/services/rag/vector_store.py`)
  - Collection per user: `user_{user_id}_memories`, cosine space (`metadata={"hnsw:space": "cosine"}`)
  - Directory: `backend/chroma_db` (named volume `chroma_data` mounted in `docker-compose.yml`)
  - Embeddings generated by sentence-transformers `all-MiniLM-L6-v2` (384-dim, downloaded from HuggingFace Hub on first use)
  - **Degradation:** if ChromaDB initialization fails, `ChromaVectorStore` transparently falls back to an `InMemoryVectorStore` (volatile, process-only — see CONCERNS.md); the embedding service similarly falls back to deterministic lightweight vectors

**File Storage:**
- Local filesystem only (SQLite DB + ChromaDB directory). No object storage / cloud file service.

**Caching:**
- None (no Redis/memcached). RAG answers are not cached between requests.

## Authentication & Identity

**Auth Provider:**
- Custom in-app JWT auth — no external OAuth/SSO provider
  - Implementation: `backend/auth.py` — PyJWT HS256, 7-day expiry (`ACCESS_TOKEN_EXPIRE_MINUTES`), bcrypt password hashing, `OAuth2PasswordBearer(tokenUrl="/api/auth/login")`
  - Endpoints: `POST /api/auth/register`, `POST /api/auth/login`, `GET /api/auth/me` (`backend/routes/auth_routes.py`)
  - Secret: `JWT_SECRET_KEY` env var — **required in production** (validator in `backend/core/config.py`); ephemeral random secret generated per-process in development (no committed default)
  - Frontend stores token in `localStorage` key `cozy_token` (`frontend/src/services/api.ts`); axios response interceptor clears it and invokes `setUnauthorizedHandler` on 401
  - Optional demo seeding `demo@cozy.app` / `cozy123` gated behind `SEED_DEMO` (non-production only — `backend/main.py` lifespan)

## Monitoring & Observability

**Error Tracking:**
- None (no Sentry/Datadog/etc.); errors surface via `logger.error`/`logger.warning` (stdlib logging, configured in `backend/main.py`)

**Logs:**
- Python `logging` module with named loggers (`cozy.main`, `cozy.auth`, `cozy.routes.tasks`, `cozy.rag.*`); per-request middleware in `backend/main.py` logs `request_id`, method, path, status, latency and sets an `X-Request-Id` response header
- Health endpoints: `GET /health/live` (liveness) and `GET /health/ready` (readiness with DB check) in `backend/routes/health_routes.py` — consumed by Docker healthchecks and CI smoke tests
- No structured logging / log aggregation

## CI/CD & Deployment

**Hosting:**
- Local Docker Compose only (`docker-compose.yml`): `db` (PostgreSQL 16), `backend` (port 8000), `frontend` (port 3000 → nginx container port 80); all services have healthchecks
- `frontend/nginx.conf` serves the SPA and reverse-proxies `/api/` → `backend:8000` (the fix for previously-broken Docker API calls)
- Backend container exposes `extra_hosts: host.docker.internal:host-gateway` so it can reach a host-machine Ollama instance

**CI Pipeline (`.github/workflows/ci.yml`):**
- `backend-ci`: Python 3.11 setup, `ruff check .`, `mypy`, `pytest` (offline suite)
- `frontend-ci`: Node 20 setup, `npm ci`, `eslint`, `tsc --noEmit`, `vitest run`, `npm run build`
- `docker-smoke-test`: `docker compose build` + `up -d`, polls `/health/ready` and the frontend, then runs API smoke tests (register → create task → complete → RAG query)
