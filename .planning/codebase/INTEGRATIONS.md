# External Integrations

**Analysis Date:** 2026-08-11

## APIs & External Services

**LLM / AI Providers (called directly via `requests` in `backend/rag_service.py` — no official SDKs):**
- **Ollama** (local, default provider) — RAG answer generation
  - Endpoint: `OLLAMA_HOST` env var, default `http://localhost:11434/api/generate`
  - Model: `llama3` (overridable via `model_name` request field)
  - Timeout: 5s; failure falls through to the next branch / rule-based engine
- **OpenAI (ChatGPT)** — optional cloud provider
  - Endpoint: `https://api.openai.com/v1/chat/completions`
  - Auth: `OPENAI_API_KEY` env var, `Authorization: Bearer`
  - Model: `gpt-3.5-turbo` (overridable)
- **Google Gemini** — optional cloud provider
  - Endpoint: `https://generativelanguage.googleapis.com/v1beta/models/gemini-1.5-flash:generateContent?key=...`
  - Auth: `GEMINI_API_KEY` env var (passed as URL query param)
  - Model: `gemini-1.5-flash` (overridable)
- **xAI Grok** — optional cloud provider
  - Endpoint: `https://api.x.ai/v1/chat/completions`
  - Auth: `GROK_API_KEY` or `XAI_API_KEY` env var, `Authorization: Bearer`
  - Model: `grok-beta` (overridable)
- Provider selection is per-request via `provider` field (`ollama` | `openai` | `gemini` | `grok`) in `backend/schemas.py` (`RAGQueryRequest`) and the dropdown in `frontend/src/components/AIAssistant.tsx`
- All cloud calls have 10s timeouts; every provider failure falls back to the built-in keyword rule engine `_generate_smart_fallback` in `backend/rag_service.py`

**Fonts CDN:**
- Google Fonts (Fredoka, Quicksand) — loaded at runtime in `frontend/index.html` from `fonts.googleapis.com` / `fonts.gstatic.com`

## Data Storage

**Databases:**
- SQLite (default) — primary relational store
  - Connection: `DATABASE_URL` env var, default `sqlite:///./cozy_productivity.db` (`backend/database.py`)
  - Client: SQLAlchemy 2.x ORM; `users` + `tasks` tables (`backend/models.py`)
  - File: `backend/cozy_productivity.db` (volume-mounted in `docker-compose.yml`)
- PostgreSQL supported via `DATABASE_URL` override (connect args adjusted automatically in `backend/database.py`) but no PostgreSQL service is configured in `docker-compose.yml`

**Vector Store:**
- ChromaDB >= 0.4.0 — RAG memory embeddings
  - Client: `chromadb.PersistentClient(path="./chroma_db")` in `backend/rag_service.py`
  - Collection per user: `user_{user_id}_memories`
  - Directory: `backend/chroma_db` (volume-mounted in `docker-compose.yml`)
  - Embeddings generated by sentence-transformers `all-MiniLM-L6-v2` (downloaded from HuggingFace Hub on first run)
  - Graceful degradation to an in-memory list (`in_memory_docs`) when chromadb/sentence-transformers import fails

**File Storage:**
- Local filesystem only (SQLite DB + ChromaDB directory). No object storage / cloud file service.

**Caching:**
- None (no Redis/memcached)

## Authentication & Identity

**Auth Provider:**
- Custom in-app JWT auth — no external OAuth/SSO provider
  - Implementation: `backend/auth.py` — `python-jose` HS256 JWT, 7-day expiry (`ACCESS_TOKEN_EXPIRE_MINUTES = 60*24*7`), `passlib` bcrypt hashing, `OAuth2PasswordBearer(tokenUrl="/api/auth/login")`
  - Endpoints: `POST /api/auth/register`, `POST /api/auth/login`, `GET /api/auth/me` (`backend/routes/auth_routes.py`)
  - Secret: `JWT_SECRET_KEY` env var with a hardcoded default fallback in `backend/auth.py`
  - Frontend stores the token in `localStorage` key `cozy_token` (`frontend/src/services/api.ts`)
  - Demo credentials seeded on startup: `demo@cozy.app` / `cozy123` (`backend/main.py` startup event)

## Monitoring & Observability

- Backend Dockerfile sets `host.docker.internal` gateway (`extra_hosts`) so the container can reach a host-machine Ollama instance

**CI Pipeline:**
- None detected (no `.github/`, `.gitlab-ci.yml`, or similar)
